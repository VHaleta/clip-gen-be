# Продуктовая спецификация — TikTok Clip Generator

## 1. Обзор продукта

Десктопное веб-приложение. Принимает видеофайл с локального диска, автоматически находит интересные фрагменты, предлагает их пользователю на проверку и правку, после чего нарезает выбранные фрагменты в вертикальный формат TikTok с опциональными субтитрами и AI-нарративом. Результат — готовые клипы для публикации.

**Целевой пользователь:** TikTok-контент-мейкер; несколько пользователей под управлением администратора.  
**Деплой:** приложение и все видеофайлы — локально (localhost / локальная сеть); база данных и хранилище API-ключей (Azure Key Vault) — в облаке. Вход по логину и паролю, без мобильной версии.

## 2. Функции приложения

### 2.1 Загрузка видео

Видео загружается только с локального диска. Загрузка по ссылкам со сторонних платформ не поддерживается.

- Drag & drop в зону загрузки
- Кнопка «Выбрать файл»
- Поддерживаемые форматы: MP4, MOV, AVI, MKV, WEBM
- Максимальный размер: не ограничен (локальный инструмент)
- Если во время загрузки заканчивается место на диске, загрузка прерывается с понятным сообщением

**Предпросмотр загруженного видео**
- Встроенный видеоплеер
- Отображение: название, длительность, разрешение, частота кадров, размер файла
- Кнопка «Начать заново» (выбрать другое видео)

**Облегчённая копия для просмотра**

Браузер воспроизводит не все форматы и кодеки из списка поддерживаемых (например, большинство AVI, MKV со звуком AC3/DTS, видео в HEVC). Для таких файлов:
- после загрузки автоматически создаётся облегчённая копия для просмотра (720p) — задача «Подготовка превью» в общей очереди, с прогрессом;
- пока копия не готова, плеер показывает статус подготовки; параметры обработки можно настраивать, анализ можно поставить в очередь;
- копия используется только для просмотра в плеере и редакторе; анализ и рендер всегда работают с оригиналом в исходном качестве;
- место, занятое копией, учитывается в объёме обработки.

Файлы, которые браузер воспроизводит напрямую, копию не получают.

### 2.2 Параметры обработки

Перед запуском анализа пользователь настраивает параметры. Часть параметров можно изменить позже в редакторе без повторного анализа — см. «Изменение параметров после анализа» (раздел 2.4).

**Клипы**

| Параметр | Варианты |
|---|---|
| Ориентировочная длина клипа | 15 сек / 30 сек / 60 сек / 90 сек |
| Количество клипов | 1 — 10 |
| Язык анализа | Авто / Русский / Английский / и др. |

Длина клипа ориентировочная: фактическая длина фрагмента, выбранного AI, может отличаться от выбранной на **±25%**, чтобы границы клипа попадали на конец фразы или паузу, а не обрывали речь на полуслове.

| Выбранная длина | Допустимый диапазон |
|---|---|
| 15 сек | 11 — 19 сек |
| 30 сек | 22 — 38 сек |
| 60 сек | 45 — 75 сек |
| 90 сек | 67 — 113 сек |

Диапазон ±25% ограничивает только выбор AI. При ручной правке тайм-кодов и ручном выборе фрагмента длина клипа может быть от 1 до 180 секунд.

**AI-модели**

| Параметр | Варианты |
|---|---|
| Модель анализа фрагментов | Список доступных моделей Gemini и Claude |
| Модель генерации нарратива | Список доступных моделей Gemini и Claude |

Правила:
- Список моделей загружается у провайдеров автоматически; в нём показываются только провайдеры, для которых администратор задал API-ключ (раздел 3.2).
- Модель выбирается пользователем явно; без выбранной модели анализ (и генерация нарратива) не запускается.
- Модель нарратива можно сменить в редакторе перед перегенерацией текста.

**Кадрирование (формат перевода в 9:16)**

| Вариант | Описание |
|---|---|
| По центру | Обрезка исходного кадра по центру до 9:16 |
| Размытый фон | Исходное видео целиком по центру кадра, сверху и снизу — его же размытая увеличенная копия |
| Ручное смещение | Обрезка до 9:16 с настраиваемым горизонтальным смещением области кадра (слайдер «левее / правее» для каждого клипа в редакторе) |
| Split-screen | Две области исходного кадра друг над другом (например, вебка сверху, игра снизу); области задаются пользователем вручную на стоп-кадре |

По умолчанию — «Размытый фон». Формат можно задать глобально и переопределить для отдельного клипа в редакторе. Все режимы работают и с вертикальными исходниками; для исходника, который уже не шире 9:16, слайдер смещения не показывается.

**Субтитры**

| Параметр | Варианты |
|---|---|
| ☑ Добавить субтитры | Да / Нет (галочка, по умолчанию включена) |
| Стиль | 2–3 пресета (например: «Слово за словом с подсветкой», «Фраза целиком», «Минимализм») |
| Позиция | Нижняя треть / Центр / Верхняя треть |

Правила:
- Субтитры вшиваются в видео при рендере.
- Если нарратив включён, субтитры строятся по тексту нарратива; если выключен — по транскрипту оригинала.
- Субтитры размещаются внутри безопасных зон TikTok (не перекрываются интерфейсом приложения снизу и справа).

**Нарратив**

| Параметр | Варианты |
|---|---|
| Включить нарратив | Да / Нет |
| Голос | Выбор из библиотеки ElevenLabs |
| Стиль комментатора | Энергичный / Нейтральный / Юмористический |
| Язык нарратива | Русский / Английский / и др. |
| Звук оригинала | Выключен / Тихий фон (8%) / Сохранить |

### 2.3 Этап 1 — Анализ

Обработка разделена на два этапа. Первый этап быстрый: он не рендерит видео и не генерирует озвучку, а только находит кандидатов и готовит черновики.

- Кнопка «Запустить анализ» — задача ставится в общую очередь
- Пока задача ждёт в очереди, отображается позиция в очереди («Перед вами 2 задачи»); задачу можно снять с очереди
- Прогресс-бар с текущим шагом:
  - Извлечение аудио
  - Транскрипция аудио
  - Анализ фрагментов
  - Генерация черновиков нарратива (если нарратив включён)
- Кнопка «Отменить» на любом шаге; уже завершённые шаги сохраняются в кэше (раздел 2.7)
- Процент прогресса и оставшееся время рассчитываются по реальному ходу текущего шага (например, по уже распознанной части аудио), а веса шагов зависят от длительности видео — прогресс не «застревает» на длинных видео
- Уведомление при завершении (в интерфейсе и системное уведомление браузера)

**Результат этапа 1:** список клипов-кандидатов с тайм-кодами, причиной выбора и черновиком текста нарратива. Переход в редактор (раздел 2.4).

---

### 2.4 Редактор кандидатов

На этом шаге пользователь проверяет и правит кандидатов перед рендером. Все клипы воспроизводятся как **превью исходника**: плеер проигрывает соответствующий отрезок оригинального видео (или его облегчённой копии, раздел 2.1), без рендера.

**Список кандидатов**
- Превью фрагмента исходника для каждого кандидата
- Тайм-коды (начало — конец в исходном видео) и фактическая длина
- Причина выбора от AI (почему этот фрагмент интересен)
- Галочка «Включить в рендер» (по умолчанию включена у всех)
- Пометка 🔴 «Озвучка длиннее клипа» у клипов, пропущенных при рендере, с действиями из раздела 2.6

**Транскрипт**
- Полный текст с тайм-кодами
- Подсветка фрагментов-кандидатов
- Клик по фрагменту — переход к нему в плеере

**Редактирование тайм-кодов**
- Слайдер для подрезки начала и конца (±30 сек от выбора AI)
- После изменения тайм-кодов — кнопка «Перегенерировать нарратив» (перегенерирует только текст, без озвучки)

**Редактирование нарратива**
- Просмотр черновика текста
- Ручное редактирование текста
- Индикатор соответствия длины текста длине клипа (раздел 2.6)

**Кадрирование клипа**
- Выбор формата кадрирования для конкретного клипа (переопределяет глобальный)
- Для «Ручного смещения» — слайдер положения кадра с превью области 9:16

**Ручной выбор фрагмента**
- Таймлайн исходного видео
- Выделение произвольного отрезка мышью
- Добавление в список кандидатов (для него можно сгенерировать черновик нарратива)

**Изменение параметров после анализа**

Параметры обработки доступны в редакторе. Что происходит при изменении:

| Параметр | Поведение |
|---|---|
| Кадрирование, субтитры | Применяется при следующем рендере |
| Голос, звук оригинала | Применяется при следующем рендере; тексты нарратива не меняются |
| Стиль, язык или модель нарратива | Существующие тексты сохраняются и помечаются «Создан с другими настройками». Кнопка «Перегенерировать тексты» для выбранных клипов; тексты, правленные вручную, перезаписываются только после подтверждения |
| Включение нарратива (если при анализе он был выключен) | Кнопка «Сгенерировать тексты» для выбранных клипов; повторный анализ не нужен |
| Длина и количество клипов, язык анализа, модель анализа | Требуется повторный анализ |

Генерация и перегенерация текстов выполняется сразу, без постановки в очередь.

**Повторный анализ**
- Кнопка «Повторить анализ» — задача ставится в общую очередь
- Извлечённое аудио и транскрипт берутся из кэша; транскрипция выполняется заново только при смене языка анализа
- Кандидаты AI, которые ещё не отрендерены, заменяются новыми вместе с их правками; ручные фрагменты и уже отрендеренные клипы сохраняются
- Перед запуском — подтверждение с указанием, сколько кандидатов будет заменено

**Запуск этапа 2**
- Кнопка «Рендер выбранных клипов (N)»

### 2.5 Этап 2 — Рендер

Рендерятся только клипы, отмеченные в редакторе. Задача рендера ставится в ту же общую очередь, что и анализ.

- Позиция в очереди, пока задача ждёт
- Прогресс-бар с текущим шагом:
  - Генерация озвучки — сразу для всех выбранных клипов, до начала рендера (если нарратив включён)
  - Рендер клипа с номером клипа (например, «Клип 2 из 5») — нарезка, кадрирование, субтитры, сведение звука и кодирование выполняются за один проход
- Кнопка «Отменить»: уже отрендеренные клипы сохраняются, незавершённый удаляется
- Уведомление при завершении; если какие-то клипы пропущены из-за длины озвучки, уведомление сообщает их количество

**Сведение звука**
- При режиме «Тихий фон» оригинальный звук приглушается до 8% только на время реплик нарратора и возвращается к обычному уровню в паузах (ducking)
- Громкость итогового клипа нормализуется до −14 LUFS

**Результаты**
- Видеоплеер для каждого готового клипа
- Клипы, пропущенные из-за слишком длинной озвучки, показываются с пометкой 🔴 и действиями из раздела 2.6
- Возврат в редактор: правка клипа и повторный рендер только этого клипа
- Скачать отдельный клип (MP4)
- Скачать все клипы одним ZIP-архивом

### 2.6 Согласование длины нарратива и клипа

Озвучка не должна быть длиннее клипа.

**При генерации текста**
- LLM получает целевую длительность и генерирует текст из расчёта ~2,5 слова в секунду, с заполнением не более 90% длины клипа (остаток — паузы)

**В редакторе**
- Рядом с текстом отображается оценка длительности озвучки и индикатор:
  - 🟢 укладывается в клип
  - 🟡 длиннее клипа не более чем на 10% — будет ускорена
  - 🔴 длиннее более чем на 10% — требуется действие
- До рендера оценка строится по числу слов, после рендера — по фактической длительности озвучки

**При рендере (после генерации озвучки измеряется её фактическая длительность)**
- Если озвучка короче клипа — никаких действий не требуется
- Если озвучка длиннее клипа не более чем на 10% — она ускоряется до 1,1×
- Если длиннее более чем на 10% — этот клип не рендерится, остальные клипы задачи рендерятся как обычно. После завершения задачи клип помечается 🔴 «Озвучка длиннее клипа» в результатах и в редакторе, и пользователю предлагаются действия:
  - **сократить текст автоматически** (через LLM) — при следующем рендере будет сгенерирована новая озвучка;
  - **удлинить клип до длины озвучки** — конец клипа сдвигается; если исходное видео заканчивается раньше, сдвигается и начало; уже сгенерированная озвучка используется повторно;
  - **отредактировать текст вручную**.
- После выбранного действия — кнопка «Отрендерить клип» (повторный рендер только этого клипа)

### 2.7 Кэширование и возобновление

Результаты каждого шага сохраняются, чтобы не выполнять дорогие операции повторно.

| Что кэшируется | Ключ кэша | Когда используется повторно |
|---|---|---|
| Извлечённое аудио | Хэш файла | Повторная обработка того же видео |
| Транскрипт | Хэш файла + язык | Повторный анализ с другими параметрами |
| Результат анализа (кандидаты) | Хэш файла + длина + количество клипов + модель анализа | Возврат к прошлой обработке |
| Черновики и правки нарратива | ID клипа | Возврат в редактор |
| Озвучка TTS | Текст + голос + стиль + модель озвучки ElevenLabs | Повторный рендер без изменения текста |

Правила:
- Хэш файла (SHA-256) вычисляется при загрузке; повторная загрузка того же файла подхватывает существующий кэш.
- Кэш общий для всех обработок одного и того же видео у пользователя. Удаление одной обработки не удаляет промежуточные файлы, которые использует другая.
- Изменение любого параметра инвалидирует только зависящие от него шаги (например, смена стиля нарратива не запускает транскрипцию заново).

**Сбои и возобновление**
- **Приложение закрыто или завершилось аварийно** (перезагрузка компьютера, падение процесса) во время обработки — после перезапуска задача продолжается автоматически, с последнего завершённого шага. После аварийного завершения возобновление может начаться с задержкой до нескольких минут.
- **Шаг завершился ошибкой** (AI-сервис недоступен, неверный ключ, повреждённый файл) — задача не повторяется автоматически, чтобы не тратить платные запросы впустую. Она получает статус «Ошибка» с понятным сообщением; кнопка «Повторить» запускает её снова с теми же параметрами, с последнего завершённого шага.
- **Отменённая задача** не возобновляется; новый запуск использует всё, что уже есть в кэше.

### 2.8 История обработок и управление хранилищем

**История**
- Список предыдущих обработок текущего пользователя
- Для каждой: название, дата, количество клипов, миниатюра, занимаемое место на диске
- Открытие прошлой обработки (в редакторе или в результатах)
- Общий объём занятого места вверху страницы
- Группировка по дням с датами в часовом поясе пользователя и относительным временем («2 дня назад»)

**Теги**
- К обработке можно добавить один или несколько тегов (например, «подкаст», «стрим»)
- Теги общие в рамках пользователя, создаются прямо при вводе
- Фильтрация истории по тегу

**Удаление файлов**

Для каждой обработки доступны действия:

| Действие | Что удаляется | Что остаётся |
|---|---|---|
| Удалить оригинал | Исходное видео, облегчённая копия для просмотра, извлечённое аудио | Готовые клипы, транскрипт, запись в истории |
| Удалить клипы | Отрендеренные клипы | Оригинал, кэш, правки — клипы можно отрендерить заново |
| Очистить кэш | Промежуточные файлы (аудио, TTS) | Оригинал, клипы, транскрипт |
| Удалить полностью | Всё: оригинал, клипы, кэш, запись в истории | — |

Правила:
- Промежуточные файлы, которые использует другая обработка того же видео, не удаляются (раздел 2.7).
- Каждое удаление требует подтверждения с указанием освобождаемого объёма; объём учитывает только файлы, которые действительно будут удалены.
- После удаления оригинала редактирование и повторный рендер недоступны; в истории запись помечается «Оригинал удалён».
- Файлы удаляются с диска физически, а не только из интерфейса.

## 3. Админ-панель

Доступна только пользователям с ролью «Администратор». Открывается по адресу `/admin` как отдельный раздел со своей навигацией, в том же тёмном оформлении.

### 3.1 Пользователи

- Список пользователей: логин, роль, дата создания, дата последнего входа, занятое место на диске
- Создание пользователя: логин, пароль, роль (Администратор / Пользователь)
- Редактирование: смена роли, сброс пароля
- Блокировка / разблокировка пользователя
- Удаление пользователя удаляет все его обработки и файлы с диска; записи журнала активности сохраняются с его логином. Чтобы сохранить данные пользователя, его можно заблокировать вместо удаления
- Нельзя удалить или заблокировать последнего администратора

### 3.2 API-ключи

API-ключи не вводятся и не отображаются в приложении. Администратор задаёт их вручную в Azure Key Vault; приложение читает их оттуда. Ключи общие для всех пользователей.

| Сервис | Назначение |
|---|---|
| Google Gemini | Анализ фрагментов, генерация нарратива |
| Anthropic Claude | Анализ фрагментов, генерация нарратива |
| ElevenLabs | Озвучка нарратива |

- Изменения ключей подхватываются приложением в течение ~5 минут, без перезапуска
- Для работы достаточно ключа хотя бы одного LLM-провайдера; модели провайдера без ключа не показываются
- Если нужный ключ не задан, соответствующая функция в интерфейсе недоступна с подсказкой обратиться к администратору
- Какие ключи заданы, видно на странице «Сводка» (раздел 3.5)

### 3.3 Очередь задач

- Текущая выполняемая задача и её прогресс
- Список задач в ожидании (пользователь, видео, тип: подготовка превью / анализ / рендер, время постановки)
- История выполненных и упавших задач с текстом ошибки
- Удаление задачи из очереди

### 3.4 Журнал активности

Единая лента событий всех пользователей, от новых к старым:
- входы в систему (успешные и неуспешные, в том числе попытки входа под несуществующим логином),
- создание обработок,
- удаления файлов (что удалено и сколько места освобождено).

Фильтры: пользователь, тип события, период.

### 3.5 Сводка

Главная страница админ-панели: общее занятое место на диске, свободное место, число пользователей, состояние очереди, доступность AI-сервисов (для каких сервисов задан ключ).

### 3.6 Доступ администратора к данным пользователей

Администратор видит служебные данные, необходимые для управления:
- список пользователей и занятое ими место;
- метаданные обработок в очереди и журнале: логин, имя файла, дата, тип и статус задачи, текст ошибки, размер.

Администратор не видит содержимое обработок других пользователей: видео, клипы, транскрипты и тексты нарратива; не может открыть их в редакторе или скачать. Как обычный пользователь администратор работает только со своими обработками.

## 4. Выходной формат видео

| Параметр | Значение |
|---|---|
| Разрешение | 1080 × 1920 (вертикальный, 9:16) |
| Частота кадров | Фиксированная, 30 fps (исходники с другой частотой конвертируются) |
| Видеокодек | H.264, профиль High |
| Битрейт видео | Фиксированный, 10 Мбит/с |
| Аудиокодек | AAC, 48 кГц, стерео, 192 кбит/с |
| Громкость | Нормализация до −14 LUFS |
| Кадрирование | По выбору пользователя (раздел 2.2) |
| Контейнер | MP4 |

## 5. Ограничения MVP

- Только десктоп (Chrome / Edge)
- Загрузка видео только с локального диска, без загрузки по ссылкам
- Задачи всех пользователей (подготовка превью, анализ, рендер) выполняются последовательно в одной общей очереди (одновременно обрабатывается одна задача); операции с текстом нарратива (генерация, перегенерация, сокращение) выполняются сразу, без очереди
- Видеофайлы, клипы и кэш хранятся только локально; в облаке — база данных и API-ключи (Azure Key Vault)
- Для работы нужен доступ в интернет (облачная база данных, хранилище ключей и AI-сервисы)
- Умное кадрирование (face tracking) — не в MVP

## 6. Нефункциональные требования

- Интерфейс на русском языке
- Тёмная тема по умолчанию
- Вход по логину и паролю; данные и история каждого пользователя видны только ему (доступ администратора — раздел 3.6)
- Прогресс обработки в реальном времени (без перезагрузки страницы)
- Корректная обработка ошибок с понятными сообщениями (неподдерживаемый формат, повреждённый файл, недостаточно места на диске, неверный или отсутствующий API-ключ и т.д.)
